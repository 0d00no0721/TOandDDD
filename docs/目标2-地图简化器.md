# 目标 2：地图简化器（脚本）：完整地图 → 碰撞结构的简化

> 输入完整地图，只渲染其碰撞几何（不加载贴图），用配色区分并把原本不可见的"空气墙"显示出来。既可实时预览，也可导出简化版地图。

---

## 1. 目标概述

### 问题背景
Tanki 地图有两套数据：
- **视觉几何**（贴图模型 `.a3d`，约 400MB 资源）—— 玩家看到的表象
- **碰撞几何**（`map.bin` 内 `collisionData`，不可见）—— 坦克实际碰撞的真实结构

两者常常不一致：
- **尖顶房子**：贴图上看是尖顶，但实际碰撞是个梯形柱
- **树**：视觉上透空（可看穿），但周围有一圈看不见的碰撞（空气墙）

### 简化器做什么
**只取碰撞几何，用纯色渲染**，于是：
- 尖顶房子 → 显示为梯形柱（碰撞的真实形状）
- 透空的树 → 显示出周围的空气墙（原本不可见的碰撞）

本质是**视觉简化**（用碰撞+纯色替代贴图模型），而非"碰撞形状数量简化"。这样无需下载 400MB 贴图即可看到地图的"真实可玩结构"。

### 产出
- **视图**：彩色碰撞预览（实时预览 / 独立 HTML 预览页）
- **导出**：简化版 map.bin（视觉几何替换为碰撞几何 + 纯色材质）

## 3. 碰撞形状语义（已破解）

来源：`editor.html:1986-2030` 的 `createCollisions()` 渲染代码（这是权威解释）。

### 三种形状类型

| 类型 | 几何含义 | 数据布局 | 渲染代码 |
|---|---|---|---|
| **type1** | OBB 有向包围盒 | `pos(3) + rot(3) + size(3)` = 9×float32 | `editor.html:1994` `BoxGeometry(d[6],d[7],d[8])` |
| **type2** | 薄片盒（墙/地面） | `length(f64) + pos(3) + rot(3) + width(f64)` | `editor.html:2003` `BoxGeometry(width, length, 5)`（厚度硬编码 5） |
| **type3** | 三角面片（每条=1三角形） | `meta(f64) + pos(3) + rot(3) + 3顶点(9×f32)` | `editor.html:2017` 3 顶点 BufferGeometry，DoubleSide |

### 两组碰撞数据
- `collisionData1`（现编辑器渲染为红色 `0xFF3333`，`editor.html:2032`）
- `collisionData2`（现编辑器渲染为绿色 `0x33FF33`，`editor.html:2033`）
- 两组渲染方式完全相同，语义上似为两个碰撞层（具体差异待实测）

### 解析入口
- `parseMapBin`（`editor.html:1183`）内的 `readCols()`（`editor.html:1234-1262`）

## 4. 配色策略

现状：编辑器仅用红/绿两色区分两组碰撞数据，无类型/区域区分。

### 扩展配色方案

| 区分维度 | 配色 |
|---|---|
| **按类型** | type1（OBB）= 蓝、type2（薄片）= 黄、type3（三角面）= 紫 |
| **按碰撞组** | collisionData1 = 暖色调、collisionData2 = 冷色调 |
| **"空气墙"高亮** | 无对应视觉模型的碰撞 = 半透明高亮色（如橙色线框） |

### "空气墙"识别
- 对比碰撞形状与视觉 `props[]`：若某碰撞形状附近无对应视觉 prop → 标记为"空气墙"
- 判定方法（待细化）：按位置/包围盒匹配，碰撞形状中心若远离任何 prop → 空气墙
- 可视化：半透明 + 线框，与有对应模型的实心碰撞区分

> 注：精确的"空气墙"识别算法需实测数据后细化——map.bin 中碰撞形状与 props 的对应关系是否显式记录？还是只能靠空间 proximity 判断？见第 8 节待定问题。

1. Node 读取 `map.bin` → 移植版 `parseMapBin` 解析出 `collisionData1/2`
