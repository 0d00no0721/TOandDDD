# 目标 1：自然语言 → 地图的生成

> 用自然语言描述需求，自动生成可在编辑器/游戏中载入的 Tanki Online 地图。

---

## 1. 目标概述

用户输入一句自然语言描述（如「两座对称山丘、中间一条沟、适合 1v1 的小图」），系统输出一份完整可用的 `map.bin`。该文件可直接在网页地图编辑器（`maps/editor.html`）中加载、编辑、导出，也可供游戏客户端使用。

**核心原则：只组合游戏现有道具库中的 props，不创造新几何体/新贴图。** 全部资源来自 `res.3dtank.com` 的 CDN 资源库。

---

## 2. 输入 / 输出

### 输入
- 自然语言文本（中文），描述地图的：
  - 整体风格（对称/非对称、开阔/紧凑）
  - 地形特征（山丘、沟壑、平原、仓库等）
  - 用途/规模（1v1、CTF、大图、小图）
  - 道具密度/类别倾向（多掩体、少掩体、工业风等）

### 输出
- `map.bin`（二进制，Tanki Online 地图格式），包含：
  - `atlases`：图集引用（来自库）
  - `materials`：材质表（引用库内贴图名）
  - `props[]`：道具实例列表（id / grpName / libName / matID / name / pos / rot / scale）
  - `collisionData1/2`：碰撞数据（导出时默认清零，参见目标 2 处理）
- 可选：一份人类可读的布局 JSON（便于审阅/微调）

---

## 3. 方法架构：LLM + 过程化混合

### 三层架构

```
自然语言描述
      │
      ▼
┌─────────────────────────┐
│  层 1：LLM 理解层         │  自然语言 → 高层结构化参数
│  (调用 LLM API)          │
└─────────────────────────┘
      │  高层参数 JSON
      ▼
┌─────────────────────────┐
│  层 2：过程化布局层       │  参数 → props 布局
│  (本地算法)              │
└─────────────────────────┘
      │  布局数据（props[]）
      ▼
┌─────────────────────────┐
│  层 3：序列化层           │  布局 → map.bin
│  (BinaryWriter)          │
└─────────────────────────┘
      │
      ▼
   map.bin
```

### 层 1：LLM 理解层
**职责**：把自然语言翻译成结构化高层参数。

**输入给 LLM 的上下文**：
- 道具库目录（从 2 个 `library.json` 提取的全部 ~2166 个 props，含分类、名称、所属库）
- Tanki 地图格式约束（坐标范围、props 结构、材质引用规则）
- 少量示例（few-shot：描述 → 对应参数）

**LLM 输出**（结构化 JSON）：
```json
{
  "style": "symmetric",
  "size": "small",
  "terrain": ["hill_left", "hill_right", "valley_center"],
  "propCategories": ["industrial", "natural"],
  "propDensity": "medium",
  "symmetry": { "type": "mirror", "axis": "x" },
  "propSelection": [
    { "category": "walls", "count": 12, "placement": "perimeter" },
    { "category": "cover", "count": 8, "placement": "scattered" }
  ]
}
```

**待定**：用哪个 LLM API（GPT-4 / Claude / 其他）？是否需要本地模型离线方案？→ 见第 8 节待定问题。

### 层 2：过程化布局层
**职责**：按高层参数，从库中具体选 props 并确定每个实例的位置/旋转/缩放。

**关键算法**：
- **道具选取**：按 `propSelection` 从库目录筛选具体 prop（按 name/category 匹配）
- **布局生成**：
  - 对称布局：对每个 prop 实例生成镜像副本
  - 密度控制：按区域面积 + 目标密度计算 prop 数量
  - 放置策略：周界/散布/聚团，避免重叠
  - 坐标系：Tanki 用 Y-up，地面在 y≈0，x/z 为水平面
- **材质分配**：每个 prop 关联其库内 matID / atlas rect

**输出**：`props[]` 数组（与 `parseMapBin` 输出同构），见 `editor.html:1304`。

### 层 3：序列化层
**职责**：把布局数据写成 `map.bin` 二进制。

**可复用代码**：
- `BinaryWriter` 类（`editor.html:790`）—— 长度前缀字符串、各种整数/浮点写入
- `wrapPacketCompressed`（`editor.html:871`）—— zlib 压缩 + 包头封装
- `packHeader`（`editor.html:845`）—— 可选位掩码头
- `generateMapBin`（`editor.html:2642`）—— 现有的 map.bin 写入逻辑（目前用于编辑器导出），可直接参考其 props/materials/atlases 写入顺序

**写入顺序**（与 `parseMapBin:1183` 读取顺序对应）：
1. 包头 + 可选位掩码
2. atlases（位1：图集块）
3. 未知对象数组（位2）
4. collisionData1（type1/2/3 三段）+ collisionData2
5. materials[]（matID / name / shader / texParams）
6. 未知对象数组（位）
7. props[]（grpName / id / libName / matID / name / pos / rot / scale）

## 4. 道具库索引

### 来源
2 个 `library.json`（已确认可从 CDN 下载，~350KB 总计）：
- `https://res.3dtank.com/553/105167/27/302/30546776460526/library.json`（Main Library，1020 props）
- `https://res.3dtank.com/570/174542/371/71/31167243462337/library.json`（New Year Library，1146 props）

### 结构（来自实测）
```json
{
  "groups": [
    {
      "name": "<分组名>",
      "props": [
        {
          "name": "<prop名>",
          "mesh": {
            "file": "<xxx>.a3d",
            "textures": [ { "diffuseMap": "<xxx>" } ]
          }
        }
      ]
    }
  ]
}
```

### 需要建立的索引
- `propsByCategory`：按 group.name 分类
- `propsByName`：按 prop.name 检索
- `propToLibBase`：prop → 其库的 baseUrl（用于生成正确的 libName 引用）

---

## 7. 约束与边界

- **只组合现有库内 props**，不生成新建模/新贴图
- **不含游戏逻辑点**（出生点 / 旗帜 / 边界）的自动放置——map.bin 的 props 只描述视觉/碰撞物件，游戏逻辑点属另一套数据（除非后续扩展）
- **碰撞数据**：生成器默认写空碰撞（与编辑器导出行为一致，`editor.html:2785`），碰撞由目标 2 的简化器后续处理
- **地图尺寸**：需确定 Tanki 地图的有效坐标范围（待从现有 map.bin 实测）
